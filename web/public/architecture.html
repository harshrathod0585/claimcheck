CLAIMCHECK ARCHITECTURE

W/P REF A-1 · System Engineering & Pipeline Specifications
Back to Verification Studio

ClaimCheck verifies every factual assertion in an investor pitch deck against a data room of SEC filings, and cites exact locations for each verdict. Two core principles drive the system design: 1. Financial numbers live inside structured tables that must never be severed by naive vector chunking, and 2. Most discrepancies are not lies — they are metrics measured on different accounting bases (e.g. Non-GAAP vs. GAAP).

System Data Flow

The model locates and reads evidence; Python determines whether claims are grounded and supported. Blue highlights LLM calls. Everything below line 04 is deterministic Python, which guarantees 100% testability with zero API spend and zero hallucinated citations.

The 4-Stage Pipeline

  1. 01Index

    Documents convert to Markdown with table grids intact. Heading id anchors are preserved for direct SEC EDGAR URL generation. Section trees hold titles and node spans but no raw text, cached by sha256 hash.

    deterministic · sha256 cached
  2. 02Extract

    The presentation deck is parsed in one LLM call. Factual statements are isolated into typed claims with periods inherited from section context. Marketing fluff and forward projections are silently filtered out.

    1 model call
  3. 03Investigate

    Claims are grouped (8 per run) so claims sharing evidence share a fetch. The agent reads section summaries, selects target sub-trees, and fetches content under a dynamic turn budget (6 + 0.5 × N).

    3 tools · batched claims
  4. 04Ground & Decide

    The agent returns raw figures — never a final verdict. Python grounds every figure against raw fetched text, normalizes scales and periods, recomputes percentages/ratios, and assigns exact verdicts.

    73 unit tests · no API key

Why Tree Navigation Beats Vector RAG

── Structure-navigating tree retrieval ───────────────────────

| (in thousands)  |   FY2024  |   FY2023  |
| Revenue         | 2,684,275 | 2,128,359 |
| Cost of revenue |   515,531 |   409,908 |

── Naive 512-token chunk & embed RAG ─────────────────────────

chunk 41  "... Total revenue  Cost of revenue  Gross profit ..."   ← labels, no numbers
chunk 42  "... 2,684,275  2,128,359  515,531  409,908 ..."         ← numbers, no labels/headers

The Chunk Severance Flaw: Slicing financial tables into arbitrary vector chunks severs numbers from header rows and scale statements (in thousands). The model attempts to guess column years, leading to off-by-1,000x errors. Tree navigation preserves HTML tables in full, keeping row labels and fiscal periods permanently attached.

Verdict Decision Hierarchy

  1. No evidence document covers the claim's fiscal period → NO_SOURCE
  2. No matching text or figure located by agent → NO_EVIDENCE
  3. Grounding Check: Figure/quote missing from fetched node text → REJECTED FINDING
  4. Compute exact value in Python (absolute, (a−b)/b growth, or a/b ratio)
  5. Agrees within rounding band & scale → SUPPORTED
  6. Matches a different accounting basis (e.g. Non-GAAP vs GAAP) → BASIS_MISMATCH
  7. Otherwise → CONTRADICTED
